# Contributing Content

This guide will eventually contain curated Minecraft mods, resource packs, shaders, and setups. Actual content is added by the repository owner. If you are allowed to contribute content, follow the rules below.

## Core rules

- Verify information before publishing.
- Prefer official project pages as sources.
- Do not fabricate compatibility information.
- Do not fabricate performance claims.
- Keep descriptions concise.
- Include Minecraft versions.
- Include mod loader information.
- Clearly distinguish client-side and server-side content.
- Credit and link the original project.
- Use screenshots only when appropriate and permitted by the project.
- Keep metadata consistent across entries.
- Use the provided templates.

## Templates

Use the matching template for every new entry:

- [Mod template](templates/mod-template.md)

## Metadata

Keep metadata consistent so entries remain comparable.

### Mods

- Category
- Minecraft version
- Mod loader
- Client / Server / Both
- Performance impact
- Compatibility
- Dependencies

### Resource packs

- Style
- Resolution
- Minecraft version
- PvP / Survival
- Performance

### Shaders

- Visual style
- Performance
- Hardware requirement
- Minecraft version
- Shader loader

### Setups

- Goal
- Minecraft version
- Mod loader
- Hardware tier
- Difficulty
- Performance

## Writing style

The site should feel like a technical but approachable Minecraft knowledge base.

Use:

- Clear headings
- Short paragraphs
- Tables where useful
- Callouts where appropriate
- Consistent terminology
- Practical explanations
- Concise technical descriptions

Avoid:

- Marketing-heavy language
- Excessive emojis
- Generic SEO spam
- Repeating the same information
- Fake specifications
- Fake performance numbers
- Invented compatibility information

## Placeholder content

Do not invent Minecraft content. Until the repository owner provides real entries, use clearly marked placeholders such as:

```text
[MOD NAME]
[DESCRIPTION]
[VERSION]
[MOD LOADER]
[IMAGE]
```
